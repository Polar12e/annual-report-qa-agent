# RAG 学习笔记：在这份 452 页年报上加向量检索与混合检索

这份笔记记录一次**带着评测做升级**的过程：把原来的单路 BM25 检索，扩展成"词法 / 概念重写 / 稠密向量 / RRF 混合"四路可切换的结构，并用四层评测集量化每一步。

最重要的结论先说清楚，因为它和大多数 RAG 教程的方向相反：

> 在这份中文年报语料上，**离线能拿到的"向量检索"没有一个能打赢 BM25**（dense 单独用 hit@1 只有 0.25~0.36）。真正把同义改写救回来的，是**词法层的概念重写**（hit@1 从 0.17 提到 0.33 于全新留出集）。向量通道的代码路径已经就绪，但要等一个真正预训练的 embedding 模型接进来，数值才有意义。

换句话说：**RAG 的上限由检索决定，检索的上限由"表示能力"决定**。这次升级把"表示能力"从"只有字面"扩到"字面 + 领域同义"，而"语义"这一格还空着，空着的原因是可复现的证据，不是没写代码。

---

## 1. RAG 的六个环节与本项目的对应代码

RAG 不是"向量库 + 大模型"，而是一条流水线。每一环的失败都会伪装成"模型不行"。

| 环节 | 它要解决的问题 | 本项目位置 | 关键参数 / 事实 |
|---|---|---|---|
| ① 摄取 | 把非结构化文档变成可检索单元 | `corpus/pages.jsonl`（452 页，418,330 字符） | 20 页无文本层，检索时跳过 |
| ② 切块 | 让一个 chunk 既能被召回、又能塞进上下文 | `src/retrieval.py::chunk_page` | 360 字符 / 80 字符重叠，按行切，避免表格行被切断 |
| ③ 表示 | 把问题与 chunk 映射到同一空间 | `src/retrieval.py::tokenize`、`src/embedding.py` | 中文 bigram；LSA 192 维；`Embedder` 协议 |
| ④ 排序 | 从 1,450 个 chunk 里挑 5 个 | `PageIndex` / `DenseIndex` / `HybridIndex` | BM25 k1=1.5 b=0.75；RRF k=60 |
| ⑤ 组装 | 把命中的页拼成上下文 | `src/tools.py::_tool_search_report` | 每段截断 400 字符、最多 3 段（`src/policy.py`） |
| ⑥ 引用与工具 | 让模型只说有据可查的话 | `src/tools.py` 的 5 个工具 + `read_page` | 数值永不由模型生成，只由工具计算 |

一个容易被忽略的事实：**④ 排序错了，⑤⑥ 再讲究也没用**。所以这次升级只动 ③④，其余保持不动，评测也只看检索指标。

## 2. 三条通道各自在解决什么

### 2.1 BM25（`bm25`）：精确匹配，基线比想象中强

中文没有空格，而项目坚持零依赖，所以用**字符二元组**（bigram）当 token：`营业收入` → `营业`、`业收`、`收入`。

- BM25 的两个参数各管一件事：`k1=1.5` 控制"词频饱和"（一个词出现 20 次不该比 10 次强一倍），`b=0.75` 控制"长度归一"（长 chunk 天然容易命中更多词，要罚）。
- 分数**不可跨查询比较**：`q13` 的 92.4 分和 `pa01` 的 19.3 分没有可比性，它们的分母不同。这就是后面必须用 RRF（只看名次）而不是"直接加权求和"的原因。

**结构先验**：查数型问题的答案通常在三大表里，而附注页会把同一个词提几十遍。于是给"报表标题页"加 18 分（`STATEMENT_BONUS`）。这个先验有多重要，实测：

| 配置 | dev hit@1 | holdout hit@1 |
|---|---|---|
| 加分 18 | 1.00 | 1.00 |
| 加分 12 | 1.00 | 1.00 |
| 加分 6 | 0.93 | 0.50 |
| 加分 0 | 0.57 | 0.00 |

**一个手写的结构先验，抵得上一堆特征工程。** 它同时说明：不查数的"解释型"问题不该享受这个加成（`NOTES_MARKERS` 里的"为什么 / 重述 / 影响 / 附注"会关掉它）。

### 2.2 概念重写（`expanded`）：把股东的话翻译成会计科目

股东问"仓库里压了多少货"，报表写"存货"。字面上零重叠，BM25 必死。

`src/lexicon.py` 是一张**领域先验表**（存货 / 应收账款 / 职工薪酬 / 分红 / 研发投入 / 利息 / 借款 / 质押 / 商誉 / 存货跌价 / 毛利率 / 资产负债率 / 经营现金流 / 汇率 / 营业收入），匹配用 bigram 而不是子串：

- `"公司一年在技术上要投多少钱"` 里没有 `技术投入` 这个子串，但有 `技术` 这个 bigram，足够判定"问的是研发投入"。
- 命中的同义项以 **0.45 的权重**加入查询。权重必须小于 1：改写只能补召回，不能让同义词盖过用户原话。
- 关键设计是**只在 OOV 压力大时才重写**（`expansion="auto"`，`coverage < 0.5`）。因为无条件重写的代价是真实的：

| 重写策略 | dev hit@1 | holdout hit@1 | holdout 明细 |
|---|---|---|---|
| 不重写 | 1.00 | 1.00 | — |
| 无条件重写 | 1.00 | **0.75** | `h04 2024年末存货是多少` 从第 1 名掉到第 5 名 |
| OOV 触发重写 | 1.00 | 1.00 | — |

`h04` 的查询本身就已经是报表用词（coverage 0.71），再塞进"仓库 / 备货 / 积压"只会稀释信号。**"何时改写"比"改写什么"更容易出错。**

### 2.3 稠密向量（`dense`）：代码就绪，表示不行

`src/embedding.py` 定义了一个只有三个成员的协议，任何模型都能插进来：

```python
class Embedder(Protocol):
    name: str
    dim: int
    def encode(self, texts: Sequence[str]) -> np.ndarray   # (n, dim)，L2 归一化
```

离线默认实现是 `LsaEmbedder`：TF-IDF 矩阵（当前语料约 21,612 个 bigram 词表）→ 随机化 SVD 取前 192 维（numpy 实现，固定随机种子，可复现）→ 余弦相似度。向量写入 `.cache/embeddings/*.npz`，键是"语料指纹 + provider 名 + 维度"，重建索引不再重算 1,450 条向量（LSA fit 仍会重新执行）。

它为什么弱？因为 **LSA 学到的是"共现平滑"，不是语义**。在 1,450 个 chunk、418k 字符的语料上，主成分几乎全部被"本公司 / 年度 / 合并 / 单位：千元"这类模板句占据，最近的邻居是共享字符的碎片：

```
库存 → 低库, 存股, 为回      （不是 存货）
分红 → 红金, 红政, 送红      （不是 利润分配）
```

我还试过把它做成"分布同义词典"（用 PMI 挖 bigram 共现邻居），结论一样：**中文的瓶颈首先是分词，不是向量维度**。字符二元组让"库存"和"存股"看起来比"库存"和"存货"更近。这条记录保留在下面"走过的弯路"里，因为它解释了为什么不建议在中文语料上跳过分词直接上向量。

### 2.4 混合（`hybrid`）：RRF 只信名次，不信分数

```python
score(page) = Σ_channels  weight_c / (k + rank_c(page)),  k = 60
```

- 只用名次，所以 BM25 的 92.4 分和余弦的 0.62 可以放进同一个式子，不需要发明一个校准函数。
- `k=60` 决定"名次差多少算差"：`1/61` 与 `1/62` 几乎相等，`1/61` 与 `1/121` 差一倍。它让前几名之间的细微差别被压平，避免某一个通道的第 1 名独裁。
- 权重编码"信任度"，并且必须能证明：稠密通道权重 0.35 时，实测**掉点**（dev hit@1 1.00 → 0.86，holdout 1.00 → 0.75）。所以默认 `DENSE_WEIGHT = 0`，混合退化为词法通道——这不是没实现，是**测量结果不允许开启**。

一个通道什么时候能进融合？当它**在自己的强项上足够强、在别人的强项上不添乱**。当前 LSA 两条都不满足。

## 3. 评测方法论（这次最值钱的部分）

### 3.1 四层数据，各防一种自欺

| split | 题数 | 用途 | 它能防什么 |
|---|---|---|---|
| `dev` | 14 | 调参、回归 | —— |
| `holdout` | 4 | 调参后从未看过的题 | 过拟合 dev |
| `para` | 8 | 同义改写诊断（口语问法） | dev 饱和后"没东西可测" |
| `para_holdout` | 6 | 概念表定稿后**新写**的口语题 | 把诊断集当训练集 |

`dev` 和 `holdout` 早就双双 1.00（14 + 4 题、全是查数型），这时候**任何改动都无法被它们评判**——满分集不能当尺子。所以造了 `para`：说人话、不给科目名。`para` 一旦被用来调概念表，它就变成了训练集，于是必须再写一份 `para_holdout` 只测不改。

这不是洁癖。第 2.2 节的 `h04` 就是活例子：无条件重写在 `dev` 上毫无变化（1.00 → 1.00），只有 `holdout` 上的那 4 道题暴露了掉点。

### 3.2 指标：hit@k 和 MRR 分工

- `hit@1` 决定用户体验（第一条引用对不对），`hit@3 / hit@5` 决定"给模型 3 段上下文时还有没有救"。
- `MRR` 对"命中但排得靠后"敏感，用来发现"排序在慢慢变差但还没掉出 top-5"的退化。
- 数值校验（11/11）必须与检索指标分开报：检索对了但数值算错，是另一种事故。

### 3.3 我踩的两个坑，写下来防止重犯

1. **标签写窄了。** `pa04`（研发投了多少钱）最初只标了第 54 页（董事会报告的"研发投入情况"表），但第 159 页利润表的"研发费用 16,232,771"同样回答了问题；`pa07`（存货计提损失）最初只标第 251 页，而第 376/220 页的"存货跌价准备"明细更直接。`pa01`（仓库里压了多少货）最初只标第 157 页资产负债表合计，但第 220/376 页的存货附注给出了分类明细，同样/更直接地回答了问题；核对原文后把 `expected_pages` 补全为 `[157, 220, 376]`。`pa06` 的 280/436 页是同一份外汇风险附注的两份副本，`pa08` 的 301 页是摘要股东表、143 页是"80% 质押阈值不适用"的说明，也分别补全了 `expected_pages`。
   **规则**：只有在原文里逐字核对过"这页确实回答了这个问题"才改标签，并且记录改动原因（就是这一段）。反过来做就是拿测试集喂模型。
2. **分数当概率用。** 一开始想"BM25 分数 + 余弦相似度"加权求和，试了一次就发现两者量纲完全无关（25 分 vs 0.62），只能靠 RRF 这种名次融合。

## 5. 为什么在这份语料上 BM25 赢

1. **查询里带锚点。** "2024年营业收入是多少" 的 `2024`、`营业收入` 都是稀疏词，BM25 的 IDF 天生擅长；dense 把它们抹平了。
2. **表格是重复文本。** 利润表/资产负债表的行文本在不同页反复出现，词法匹配能把"数值所在页"顶上来，向量相似度则把这些页视为几乎相同。
3. **语料太小。** 418k 字符 ≈ 一本 150 页的书，不足以让共现统计收敛出语义结构；预训练模型的价值恰恰在于它不从零学。
4. **中文没分词。** bigram 把"库存/存股"变得比"库存/存货"更近，这一步就把语义通道的地基挖空了。

## 6. 换成真模型：三行代码 + 一张校准清单

```python
from src.embedding import OpenAICompatibleEmbedder
from src.retrieval import build_index

embedder = OpenAICompatibleEmbedder(model="bge-m3", base_url="http://127.0.0.1:11434/v1", dim=1024)
index = build_index("hybrid", embedder=embedder, dense_weight=0.35)
```

`OpenAICompatibleEmbedder` 已经处理：批大小、`index` 字段乱序、非 2xx 不重试（4xx 直接报错）、超时重试 2 次、维度不符立刻报错（避免悄悄写坏缓存）。端点校验目前只在 `OpenAIPolicy` 实现；embedding 路径尚未接入 `src/policy.py`，接外部 embedding 前需要补齐。

接完必须重做的校准：

1. **`dim` 手填**：协议没有自动探测，填错会在第一批就抛 `EmbeddingError`（这是刻意的）。
2. **归一化**：provider 返回后统一 L2 归一化，别让余弦变成"点积排名"。
3. **前缀**：BGE 系列查询侧要加 `为这个句子生成表示以用于检索相关文章：`，文档侧不加。加错前缀比不做向量检索更糟。
4. **重测四层**：`dev`/`holdout` 不能掉，`para_holdout` 必须涨。只涨 `para` 不算数——那是你看过的题。
5. **权重从 0.2 起**：一次只调一个旋钮，先确认"不掉点"再谈"涨点"。

## 7. 走过的弯路（都是真跑过的）

| 尝试 | 结果 | 结论 |
|---|---|---|
| LSA + max_df 0.05/0.15/0.4 × 192/384 维 | dev hit@1 0.29~0.36 | 维度不是瓶颈，表示不是语义 |
| bigram 共现挖同义词典（PPMI） | `库存 → 低库/存股`；`赊账` 直接 OOV | 中文先要分词，否则邻居是字符碎片 |
| "概念通道"独立成一路再融合（关掉结构先验） | dev 1.00 → 0.79 | 结构先验比概念召回更值钱，不能为了融合把它关掉 |
| 稠密通道权重 0.35 融合 | dev 0.86 / holdout 0.75 | 弱通道会劫持排序，权重必须能被证伪 |
| OOV 触发重写（0.5 阈值） | dev/holdout 不掉，para 提升 | 保留，成为默认 |

## 8. 下一步（按性价比排序）

1. **接一个真 embedding 模型**（bge-m3 / text-embedding-3-large / 本地 Ollama），只看 `para_holdout` 是否变绿。代码不需要改。
2. **补分词**（词典 + 最大匹配，或引入 `jieba`），让 bigram 退化成词，词法通道也会涨；这是把 4 条"字符碎片"问题一起解决的唯一办法。
3. **给 `para` 补"解释型"题**（为什么重述、影响多少），现在 8 题里有 6 题是查数。
4. **重排（rerank）**：检索回 20 条，用 cross-encoder 或 LLM 打 3 条。小语料上比重建索引便宜。
5. **上下文组装**：目前按页拼 400 字符，表格列容易错位；可以按"行块"组装并保留行号，让模型引用到行。
